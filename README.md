# 🐢 海龟汤 QQ 机器人

把「海龟汤」游戏搬进 QQ：**你的小号当主持人**（由 DeepSeek 判答），私聊它或把它拉进群，全员提问、扶汤、复盘。

架构：`QQ 小号(NapCat/OneBot) ←→ 桥接服务(本目录) ←→ DeepSeek API(主持人)`

---

## ⚠️ 风险声明（先看）

- 腾讯**禁止第三方协议登录**，NapCat 属于非官方登录，**小号有被冻结/风控的风险**。
- 务必使用**不重要的号**，不要用大号；登录频率正常、不要发广告。
- 本工具仅供学习娱乐，风险自负。

## 一、安装 NapCat（让小号上线）

1. ✅ **本机已装好 QQ（NT 版）**：`C:\Program Files\Tencent\QQNT`（当前 9.9.29.47354）。
2. ✅ **NapCat v4.18.19 已下载并解压**：`setup\NapCat-Shell\`（自带依赖，用系统 Node 24）。
   - 进入 `setup\NapCat-Shell`，**先关闭正在运行的 QQ**，然后双击 `launcher-win10-user.bat`。
   - 若提示权限/写 QQ 目录失败：**右键 → 以管理员身份运行**。
   - ⚠️ 版本提示：NapCat 包对应 QQ 9.9.22，本机 QQ 是 9.9.29 —— 大概率能用（官方已跟进 47354 适配）；若启动报版本不匹配，告诉我，我们再处理。
3. 启动后会拉起 QQNT 并启动 **NapCat WebUI**：浏览器访问 `http://127.0.0.1:6099/webui`，首次需设置一个访问密码。
4. 在 WebUI 里**扫码登录你的 QQ 小号**（显示在线即成功）。
5. 配置 OneBot 接口：WebUI → **网络配置** → 添加 **WebSocket 服务器**，端口填 **3001**，启用保存。
   - 之后 NapCat 会在 `ws://127.0.0.1:3001` 提供 OneBot v11 服务（桥接服务默认连这里）。

> 若你用的 NapCat 版本菜单不同：只要最终能用 `ws://127.0.0.1:3001` 连上即可，端口可在 `.env` 里改。

## 二、配置并启动桥接服务

```powershell
cd qq-turtle-soup
Copy-Item .env.example .env      # 然后编辑 .env
```

在 `.env` 里填写：

| 变量 | 说明 |
| --- | --- |
| `DEEPSEEK_API_KEY` | **必填**。到 https://platform.deepseek.com 申请，形如 `sk-xxxx` |
| `ONEBOT_WS_URL` | 默认 `ws://127.0.0.1:3001`，NapCat 端口对得上就不用改 |
| `MAX_QUESTIONS` | 每局提问上限，默认 20 |
| `ADMIN_QIDS` | 允许开局的管理员 QQ 号（逗号分隔）；留空 = 任何人都能开局 |

启动（需要 Node ≥ 22，零依赖，无需 npm install）：

```powershell
node src/index.js
```

看到 `✅ 已连接 NapCat，等待消息…` 即成功。

> 联调小工具：NapCat 上线后，跑 `node tools/send-test.js --user <你的QQ号> "🐢 海龟汤主持人已上线"` 可验证发送链路。

> 不依赖 QQ/API Key 的自测（`test/` 目录）：
> - `node test/smoke.js` —— 状态机冒烟测试（指令路由与各阶段流转）
> - `node test/integration.js` —— 本地 Mock DeepSeek，端到端完整一局（开局→提问→还原度→扶汤→复盘）
> - `node test/ws-e2e.js` —— 自建伪 OneBot 服务器，验证真实 WS 连接与收发（群/私聊）

## 三、日常运行与故障排查

### 启动顺序（重启电脑后）

**推荐一键启动**：双击 `qq-turtle-soup\一键启动.bat` —— 自动开两个窗口：NapCat（QQ 小号，可能要扫码）+ 桥接服务（看到「已连接 NapCat」即在线，崩了自动重启）。

手动方式（等价）：

1. 双击 `setup\NapCat-Shell\launcher-win10-user.bat`（先关 QQ；权限问题右键管理员运行）→ 小号上线（可能要重新扫码）。
2. 开一个**终端窗口**（PowerShell），运行：

   ```powershell
   cd qq-turtle-soup
   .\start-bot.ps1
   ```

   - 脚本自动检查 `.env` Key 与 NapCat 3001 端口，就绪后启动桥接服务
   - **内置自动重启**：进程意外退出 5 秒后自动拉起；环境没就绪时每 10 秒重检
   - 看到 `✅ 已连接 NapCat，等待消息…` 即在线；**窗口别关**

### 机器人「没反应 / 像卡死」了怎么办

按顺序排查：

1. **NapCat 还活着吗**：浏览器开 `http://127.0.0.1:6099` 看 WebUI；或执行 `node tools/probe.js 5`（能连上且显示机器人账号在线 = NapCat OK）
2. **桥接服务还活着吗**：看 `start-bot.ps1` 的窗口
   - 窗口显示「⚠️ 进程退出，5 秒后自动重启」→ 等几秒即恢复
   - 窗口没了 → 重新运行 `.\start-bot.ps1`
3. **API 问题**：机器人日志出现 `⚠️ 判定失败（DeepSeek API …）` → API Key 失效或余额不足，检查 `.env` / 平台余额
4. 还不行：`node tools/probe.js 10` 把输出发给我

> ⚠️ 已知现象：若用「后台任务」方式启动桥接服务（非终端窗口），进程可能在会话切换时被系统回收导致失联——所以推荐用 `start-bot.ps1` 常驻终端窗口。

### 常用工具

| 命令 | 作用 |
| --- | --- |
| `.\start-bot.ps1` | 启动桥接服务（自检 + 自动重启，推荐常驻） |
| `node tools/send-test.js --user <QQ号> "内容"` | 机器人主动发一条消息（验证发送链路） |
| `node tools/probe.js [秒数]` | 机器人账号/好友/群状态 + 监听消息流（验证收发） |
| `node test/smoke.js` / `integration.js` / `ws-e2e.js` | 三套自测 |

## 四、玩法（私聊 / 群通用）

| 你发 | 机器人 |
| --- | --- |
| `题库` | 列出内置题库（玩家模式：汤底对玩家保密，可当纯玩家玩） |
| `开局 题库 序号` | 用题库题目开局（例：`开局 题库 1`） |
| `开局 汤面：… 汤底：…` | 自己出题开局（作者模式），展示汤面，封存汤底并拆成 N 个关键真相点 |
| （或先发 `开局`，再分别补发 `汤面：…` / `汤底：…`） | 发齐自动开局 |
| 任意问题（如 `他是被杀的么？`） | 只答 **是 / 不是 / 无关**，并报还原度、剩余提问 |
| `扶汤` | 给一句指向下一关键点的提示（记录次数） |
| `记录` | 回看全部提问与回答 |
| `复盘` | 进入复盘；下一条消息发完整还原 → 逐点判定 + 判定是否大致准确 + 揭晓汤底 |
| `揭晓` / `放弃` | 直接揭晓汤底 |
| `重开` | 重置本会话，开新局 |
| `规则` | 帮助 |

**两种玩法**：
- **玩家模式**：发「题库」选内置题目 → 汤底对你保密，你当纯玩家提问，有悬念
- **作者模式**：`开局 汤面：… 汤底：…` 自己出题 → 你当出题人，朋友提问（你自己知道答案属正常，玩的是别人）

**智能指令识别**：常见指令本地秒回（记录/扶汤/复盘/揭晓/还原度等，换说法也认，如「看下记录」「给我个提示」「不想玩了」）；拿不准的消息交给 AI 判断是指令还是问题，一次调用同时完成分类与判答。

还原度 = 已触及关键真相点 / 总关键点，扶汤也会点亮对应点。题库扩充：编辑 `src/puzzles.js` 照格式加即可；存档题存于 `data/saved-puzzles.json`（私聊「存题」→ 群里「开局 存题 序号」）。

## 五、常见问题

- **连不上 / 一直重连**：NapCat 没开 WebSocket 服务器或端口不对；或小号没登录。
- **机器人没反应 / 失联**：见「三、日常运行与故障排查」（先查 NapCat → 再查桥接服务进程）。
- **收得到消息但机器人不回复（事件不推送）**：多半是 **QQ 自动更新了**，NapCat 包后端的支持版本对不上。NapCat 启动日志会出现 `PacketBackend 不支持当前QQ版本架构：9.9.xx-xxxxx`。处理：等 NapCat 更新；或降级 QQ 到受支持版本（如 9.9.29）并关闭 QQ 自动更新。验证事件是否推送：`node tools/probe.js 30`，期间发条消息看监听是否抓到。
- **判答失败（DeepSeek API 报错）**：检查 `.env` 的 API Key；API 余额不足也会报错。
- **判定不够准**：汤底写详细些；或把 `src/host.js` 里 `temperature` 调低。
- **还原度乱跳**：关键点由模型开局时提取，汤底越结构化越稳。
